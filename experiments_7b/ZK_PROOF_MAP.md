## 第三层：单个 Attention Softmax 的 ZK 证明流

```
输入: Attention Scores = QK^T/√d  [1 × 32 × 2048 × 2048]
      (1 batch, 32 heads, 2048 seq)

╔═══════════════════════════════════════════════════════════════╗
║              Softmax ZK 证明 (PolyAttn)                       ║
╠═══════════════════════════════════════════════════════════════╣
║                                                               ║
║  Phase A: 输入范围检查                                        ║
║  ────────────────────                                         ║
║  对每段 k ∈ {0..7}:                                          ║
║    ZK: tlookup                                                ║
║    Prover 提交: ⟦X^(k)⟧ (1个 Pedersen 承诺)                  ║
║    Verifier 检查: X^(k)[i] ∈ [0, 255]                        ║
║    ┌──────────────────────────────────────────┐              ║
║    │ 8 段 × 1 commit = 8 额外提交             │              ║
║    │ 复用 zkLLM tlookup, 不动                 │              ║
║    └──────────────────────────────────────────┘              ║
║                                                               ║
║  Phase B: 多项式求值验证 ★ PolyAttn 核心 ★                    ║
║  ────────────────────────                                     ║
║  对中间段 k ∈ {4, 5, 6} (3段):                               ║
║                                                               ║
║    B.1: Prover 计算                                           ║
║         T_9 = [c_9]                (常数张量, 不提交)          ║
║         T_8 = T_9 ⊙ X^(k) + c_8   (Hadamard + 标量加)       ║
║         T_7 = T_8 ⊙ X^(k) + c_7                              ║
║         ...                                                   ║
║         Y^(k) = T_0 = T_1 ⊙ X^(k) + c_0                     ║
║                                                               ║
║    B.2: Prover 提交                                           ║
║         ⟦T_1⟧, ⟦T_2⟧, ..., ⟦T_8⟧ (8个 Pedersen 承诺)       ║
║         ⟦Y^(k)⟧ = ⟦T_0⟧            (1个 Pedersen 承诺)      ║
║         ┌──────────────────────────────────────────┐         ║
║         │ zkLLM tlookup: 提交 T_X(65536) + T_Y(65536)│        ║
║         │ PolyAttn: 提交 9个中间张量(每段262K元素)    │        ║
║         │ 总计: 9×(d+1)=90个张量提交 vs 2×65536表   │        ║
║         │ 提交体积对比: 90×262K / 131K ≈ 180×小     │        ║
║         └──────────────────────────────────────────┘         ║
║                                                               ║
║    B.3: Verifier — Hadamard Sumcheck (每步)                  ║
║         对 t = 0..8 (9步):                                   ║
║           V→P: 随机挑战 u ∈ F^{log₂(262144)}                ║
║           P→V: sumcheck 多项式 (18轮, 每轮3个系数)            ║
║           P→V: ProveEval(⟦T_t⟧, r)                          ║
║           P→V: ProveEval(⟦T_{t+1}⟧, r)                     ║
║           P→V: ProveEval(⟦X^(k)⟧, r)                       ║
║           V: 验证 g_mle(r) = 0                               ║
║         ┌──────────────────────────────────────────┐         ║
║         │ zkLLM: 每段1次复杂sumcheck(LogUp式14)     │         ║
║         │ PolyAttn: 每段9次简单sumcheck(Hadamard)   │         ║
║         │ 简单×9 vs 复杂×1: 通信量×9, 但每步>10×简单│        ║
║         └──────────────────────────────────────────┘         ║
║                                                               ║
║    B.4: Verifier — 同态检查                                  ║
║         com(T_t) = com(T_{t+1} ⊙ X^(k) + c_t)              ║
║         用 Pedersen 加法同态性验证                             ║
║         ┌──────────────────────────────────────────┐         ║
║         │ zkLLM: 验证 A=1/(β+S_i) 域求逆          │         ║

║         │ 无需域求逆 !                             │         ║
║         └──────────────────────────────────────────┘         ║
║                                                               ║
║  Phase C: 最高段验证                                          ║
║  ──────────────                                               ║
║  段 k=7: Y^(7) = 1{X^(7) = 0}                               ║

║    复用 zkLLM, 不动                                            ║
║                                                               ║
║  Phase D: 乘积验证                                            ║
║  ────────────                                                 ║

║                                                               ║
```

## 第四层：PolyEval vs tlookup — 单段开销对比

```
每个 Attention Head (128 × 2048 = 262,144 元素)

┌────────────────────┬──────────────────┬──────────────────┐
│ 阶段               │ zkLLM (tlookup)  │ PolyAttn (ours)   │
├────────────────────┼──────────────────┼──────────────────┤
│                    │                  │                  │
│ Setup (段提交)     │ 2×65536 = 131K   │ 0                │
│  表/系数大小       │ 提交2个查找表    │ 10个F_p标量(公开)│
│  提交操作          │ 2次Pedersen      │ 0               │
│                    │ (每个65536项)    │                 │
│                    │                  │                  │
│ Prover 计算        │ 查表: 262K次     │ Horner: 262K×9  │
│  每元素操作        │  读T_X + 读T_Y  │  9乘+9加(F_p)   │
│  域求逆            │ 262K次           │ 0 ★             │
│                    │ (~100mul/each)   │                 │
│                    │                  │                  │
│ Prover 提交        │ m,A,B,S 4个张量  │ T_1..T_8 8个    │
│  提交数量          │ + 1表提交 = 5    │ + Y + X = 10    │
│  提交复杂度        │ 5×262K项         │ 10×262K项       │
│                    │                  │                 │
│ Sumcheck           │ 1次 LogUp式(14)  │ 9次 Hadamard    │
│  每轮复杂度        │ O(D·logD) + 求逆 │ O(D) · 9轮      │
│  PCS Opening       │ 5次              │ 3×9=27次 ★      │
│   (可批量合并)     │                  │ → 批量后 ~3次   │
│                    │                  │                 │
│ Verifier 检查      │ 1次复杂等式      │ 9次简单等式     │
│  域求逆            │ 需验证A=1/(β+S)  │ 无需验证求逆 ★  │
│                    │                  │                 │
├────────────────────┼──────────────────┼──────────────────┤
│ 每元素等价乘法     │ ~115 mul         │ ~72 mul         │
│  (理论计数)        │ (100求逆+10SC    │ (9 Horner+45SC  │
│                    │  +5 commit)      │  +18 commit)    │
│                    │                  │                 │
│ 每段总开销(理论)   │ 262K×115=30.1M   │ 262K×72=18.9M   │
│ 单段加速比         │ 30.1/18.9        │ = 1.6×          │
└────────────────────┴──────────────────┴──────────────────┘

★ zkAttn 总体加速 11.1× 的原因:
  - 段 0-3: 常数1, tlookup需要提交表, PolyEval不需要
  - 段 7: indicator, tlookup需要tlookup, PolyEval也一样
  - 段 4-6: 3段PolyEval vs 3段tlookup, 每段1.6×
  - 总: (4×0 + 3×1.6× + 1×1×) / (4×1 + 3×1 + 1×1) = 很复杂
  - 简化: 主要收益来自段0-3省掉的表提交 + 中间段1.6×
```

## 第六层：PolyAttn 到底改了什么 — 一句话版

```
zkLLM 的 zkAttn 协议:
  对于 attention score z:
    1. 查表 T_X  → "z 在 [0, b-1] 范围内"
    2. 查表 T_Y  → "exp(-λz) 等于这个值"
    3. 计算 A = 1/(β + S_i)  → ★ 域求逆, ~100×乘法
    4. Sumcheck 验证

PolyAttn 的 PolyEval 协议:
  对于 attention score z:
    1. 查表 T_X  → "z 在 [0, 255] 范围内"         [保留]
    2. Horner 求值 → p(z) ≈ exp(-λz)              [★ 替换查表]
    3. 没有求逆 → 只有乘法和加法                    [★ 消除瓶颈]
    4. Hadamard Sumcheck 验证                     [简化]

差异:
  提交:  zkLLM 提交 2 个表 (每个 65536 项) + 4 个张量
        PolyAttn 提交 0 个表 + 10 个张量          [系数公开 省表提交]

  计算:  zkLLM 每元素 1 次求逆 + 2 次查表
        PolyAttn 每元素 9 次乘法 + 9 次加法       [求逆 → 乘法]

  验证:  zkLLM 1 次复杂 LogUp sumcheck
        PolyAttn 9 次简单 Hadamard sumcheck       [复杂×1 → 简单×9]
```
